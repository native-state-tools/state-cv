About and privacy

State CV is a local-first application: your CV content stays on your device. The app may download its own static files and updates from the same origin that hosts it. Choosing Support, the contact email, or another outside link leaves this page. Those links do not receive your CV.

Master CV and versions

You edit one master CV, one section at a time: Contact, Summary, Experience, Education, and Skills. A tailored version stays linked to that master. It is not its own copy. It records a name, which entries, bullets, and skills to hide, and an optional title, summary, and file name. Changing the master can change what a version shows. Preview, PDF, and plain text follow the version you are viewing.

What is stored

State CV keeps the following values in this browser. Browser storage is not a guarantee. The browser can clear it.

  • state-cv-data-v1 holds the master CV and any tailored versions, in one local record. It includes a revision for detecting conflicting edits in another tab. Versions stay linked to the master, so they are not independent copies.
  • state-cv-snapshots-v1 holds up to five recent local snapshots.
  • state-cv-damaged-v1 holds an unchanged copy of saved data that could not be read. That copy is not removed automatically. Saving stays blocked until you import a JSON backup or explicitly start a new CV.
  • state-cv-persistence-v1 holds the result of the browser persistence request: granted, not granted, or unavailable.
  • state-cv-backup-reminder-v1 holds backup reminder counters only. It contains no CV content.
  • state-cv-premigration-v1 holds one unchanged copy of a draft saved by an older version, taken before that draft is saved in the current format. It is not overwritten.

Where it is stored

Only in this browser on this device.

What is never sent

Your CV content, keystrokes, and files are processed in your browser. State CV does not send CV data, identifiers, or usage information to a server. There is no account, no analytics, and no tracking. Loading this site still requests its own pages and updates. That is separate from CV processing.

Copy as plain text writes to this browser's clipboard. Download .txt saves a local file. Neither one sends the CV over the network. ATS tips in Export, and the same checks in Review suggestions, run locally in the browser and send nothing anywhere. They are not a guarantee that every applicant tracking system will read an export the same way. CV completeness is calculated in the browser from the master CV and is not sent anywhere. App updates are downloaded from the same origin and contain no CV content, identifiers, or usage data.

How to remove it

Open Your data and choose Clear all data. That clears the draft, snapshots, damaged copy, persistence result, premigration copy, and backup reminder from this browser. You can also remove them by clearing this site's data in the browser.

Backups

Backups are your responsibility. Because data lives only in your browser, back up what matters to you. A persistence grant does not replace a JSON backup, and it does not guarantee the browser will keep the CV. Menu holds Backup (JSON) and Your data. Importing a JSON backup replaces the current master CV and versions with the backup. An older backup with no versions replaces your current versions with none. Importing a PDF removes existing versions. The question mentions a snapshot only when one is kept.
